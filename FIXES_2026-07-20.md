# Fixes — 2026-07-20 (Session 5: RL data integrity + cross-market contamination)

## Critical bugs found and fixed

### 1. Market-inference substring bug (THE root cause of cross-market chaos)
`"_st" in state_filename` matched **"_state"** in `portfolio_state.json`,
`portfolio_state_cx.json`, `portfolio_state_fx.json` — so US, STOCKS, CRYPTO
and FOREX engines ALL resolved to `market="STOCKS"` and shared **one** DB
portfolio row and one set of RLWeight rows (only INDIA escaped via the `_in`
check running first). Same bug in `rl_engine.save_state/load_state`.

**Observed damage:** forex book was a 35/35 exact alias of the US book (never
traded a single forex pair); crypto engine held and managed MSFT positions;
DB "STOCKS" row contained the US engine's state; CRYPTO/FOREX rows didn't exist.

**Fix:** suffix-of-stem matching (`stem.endswith("_st")`) in
`execution/smart_execution.py` and `analytics/rl_engine.py`
(`_infer_market_from_filepath`).

### 2. Synthetic RL seed data froze all learning
`scripts/cold_start_rl.py` seeded 100 random fake trades (55% WR, avg +$28)
into every engine — this is what `/analytics/rl-stats` was reporting, not real
performance. Worse: seeds lacked `capital_allocated` (defaulted to 1.0), so
`pnl_pct` was inflated ~100x (observed 11,686%), blowing up the rolling-30 std
used for Sharpe-reward normalization → every real trade's reward ≈ 0 →
**weights frozen at ~1.0 through 20 retrains**.

**Fix:** `_sanitize_history()` in rl_engine drops |pnl_pct| > 50% entries on
every load, recomputes counters, and resets weights/priors when contamination
is heavy. Seeder now emits `capital_allocated`; old seed file renamed to
`rl_seed_trades.json.disabled`; `pre_seed_from_backtest` guards the default.

### 3. rl_metadata clobbered on every trade save
`smart_execution._save_state_db` replaced `Portfolio.state_data` wholesale,
wiping the `rl_metadata` key that `rl_engine.save_state` writes into the same
blob (no portfolio row had rl_metadata). **Fix:** preserve existing
rl_metadata when writing the portfolio payload.

### 4. Cross-market book contamination (data cleanup)
`_sanitize_cross_market()` in smart_execution now drops holdings/closed trades
whose symbol belongs to another market's engine (`.NS`→INDIA, `=F`→US,
`=X`→FOREX, `-USD`→CRYPTO, else STOCKS). If an engine's book was 100% foreign
(forex), its balance resets to initial.

### 5. INR/USD mixing in global circuit breaker
`GlobalRiskAggregator.total_equity()` summed the Indian engine's INR equity
raw with USD books (~90x undercount of INR moves). **Fix:** INR converted at
`INR_USD_RATE` (env-overridable, default 0.0116).

### 6. Trailing stop tighter than initial stop (target starvation)
Live data: 82 stop exits vs 26 target exits; realized RR 1.17 vs configured
2.0. Trail (2.0 ATR / 0.4% floor) was tighter than entry stop (2.5 ATR / 0.5%
floor) while the target sat 5 ATR away. **Fix:** `TRAIL_ATR_MULT` 2.0 → 2.5,
trail floor 0.4% → 0.5% (`risk/adaptive_stops.py`).

## Migration required (run once, server stopped)
```
cd backend
python scripts/migrate_market_rows.py
```
Rebuilds each `portfolio` DB row from that engine's own JSON file (never
aliased), deletes shared/garbage rl_weights rows, strips polluted rl_metadata.
Then start the backend; per-engine sanitizers clean the rest on load. Expect
log lines: `[RL Engine] Sanitized: dropped 100 synthetic/corrupt trades...`
and `[SmartExecution:FOREX] Book was entirely foreign...`.
