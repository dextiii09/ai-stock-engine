   (`analytics/rl_engine.py`) — list→dict conversion defaulted missing

   `__init__` ran 3 real yfinance backtests per instance (15 network calls
   before the port could bind); `tick()` ran one inside the trading loop every
   5th call. Both now run in background daemon threads. Server startup went

   (`analytics/lstm_model.py`, `agents/ppo_master.py`) — TickLSTM and the PPO
   policy net never loaded trained weights, so they emitted signals from
   randomly initialized networks. Both now return WAIT unless a trained

   import (`lstm_model`, `ppo_master`); missing `redis` crashed

   degradation.

6. **No exit slippage model** (`execution/smart_execution.py`) — audit finding;

## 2026-07-12 addendum — "only 4–5 trades per week" root cause

Journal analysis across all 5 markets showed the Monte Carlo gate caused 50 of
54 non-weekend vetoes (US 19, Stocks 26, India 5), with observed EVs of
+0.016%…+0.12% — all positive but below the 0.15% hurdle. (The 120 forex
EVENT_BLACKOUT vetoes were just "Market Closed (Saturday)"; the 4 MTF vetoes
were legitimate.)

**Root cause** (`analytics/simulator.py`): `_win_rate_to_daily_drift` mapped
win rate → GBM drift assuming SYMMETRIC barriers: logit(0.5) = 0 drift at a
50% win rate. But the engine's stops are asymmetric (TP ≈ 2.5 ATR vs
SL ≈ 1.5 ATR), so zero-drift paths hit the nearer stop first ~62% of the time
→ EV ≈ 0 → veto. With the RL state at exactly 50/100 wins, the gate blocked
virtually every signal, and because trades were blocked, the win rate could
never update — a cold-start deadlock.

**Fix:** new `_calibrate_drift_asymmetric()` solves the exact two-barrier
first-passage equation P(win first) = (e^{θl}−1)/(e^{θl}−e^{−θw}) by bisection
so the model's TP-first probability matches the realized win rate at the
ACTUAL barrier distances (mirrored for shorts).

Verified against the real code path (20k-path runs):
| scenario | before | after |
|---|---|---|
| LONG, p_win=0.50 | EV ~0.02–0.15% → VETO | EV +0.78% → PASS |
| SHORT, p_win=0.50 | (same flaw) | EV +0.81% → PASS |
| LONG, p_win=0.33 | veto | EV −0.08% → still VETO (correct) |
| cold start (p_win=None) | bypass | bypass (unchanged) |

The gate now passes signals when realized win rate supports the R:R and still
vetoes negative-edge setups. Expect trade frequency to rise substantially;
the RL engine will finally accumulate real outcomes and self-calibrate.

## 2026-07-12 addendum 2 — flat backtest equity curve ("straight line")

Reproduced with synthetic data: **AI Committee backtests executed 0 trades**
(flat equity line) while all 7 indicator strategies traded normally. AI
Committee is the default strategy in the UI, so backtests appeared broken.

**Root cause: 1-minute calibrations applied to daily bars.** The committee
agents and regime detector were tuned for the live 1-min tick loop, but the
backtester feeds daily bars, where ATR% and VWAP distances are ~10x larger:

1. `TechnicalAgent` volatility filter (ATR > 0.3% of price → WAIT) tripped on
   every daily bar — the agent voted WAIT on 100% of backtest bars.
2. `TechnicalAgent` VWAP proximity bands (±0.5%/±0.2%) could never be
   satisfied at daily RSI extremes (an RSI<20 selloff sits far below the
   20-bar VWAP) — mean-reversion rules unreachable.
3. `VolatilityAgent` spike threshold (1.5%) → chronic WAIT on daily bars.
4. `regime_detector._fallback_detect` (ATR% > 0.5 → "News Shock") classified
   every daily bar as High Volatility → strictest consensus threshold.
5. Backtest passed `vol_zscore` but LiquidityAgent reads `volume_z` → the
   Liquidity agent saw a dead market on every bar (key mismatch).

**Fixes:** shared `_INTERVAL_ATR_SCALE` map (1m=1x … 1d=10x … 1mo=45x);
backtest passes `bar_interval` in its data dict; TechnicalAgent,
VolatilityAgent, and the regime fallback scale their ATR%/VWAP thresholds by
it (live ticks omit the key → scale 1.0 → live behavior unchanged); engine now
passes `volume_z`; benchmark floats cast for JSON safety.

**Verified:** all 8 strategies run with realistic equity curves; committee
conviction now reaches 0.57 with proper 4-agent consensus (was capped ~0.25);
regimes vary instead of pinning to High Volatility; full pytest suite still
green (12 passed, 2 torch-skips). Note: sandbox runs lack live COT/macro
data, so AI Committee trade counts will be higher on the real machine.

## 2026-07-12 addendum 3 — deep quantitative audit

Property-tested the money math end-to-end against the live engine code.

**Bugs found & fixed:**

1. **Short-position equity double-count** — opening a short deducts only 10%
   margin from cash, but holding "value" = full notional + P&L. Every place
   that computed `capital = cash + Σ value` therefore overstated equity by
   ~90% of short notional, skewing risk %, drawdown and exposure metrics.
2. **Cash-only capital fed to the risk manager in all 3 trading loops** —
   opening a LONG made "capital" (raw cash) drop by the position's full cost,
   which looked like an instant intraday drawdown and could spuriously trip
   the daily-loss circuit breaker right after entries.
   → Both fixed by new `SmartExecutionEngine.get_total_equity()` (cash + LONG
   mark-to-market + SHORT margin+P&L), now used at all 13 call sites in
   routes.py (risk endpoints, reports, and the halt-check inside each loop).
3. Cosmetic: SELL/SHORT fill messages truncated fractional contracts with %d
   ("FILLED SELL of 0 contracts") → %.4g.

**Verified clean (property tests on real code):**
- Execution accounting: LONG and SHORT round trips, force_close both
  directions — reported P&L == balance delta to the cent; exit slippage
  always adverse; margin refund exact.
- Equity invariance: opening a short leaves equity unchanged; a +1% adverse
  move reduces equity by exactly shares×Δprice.
- Backtest engine: final_equity == initial + Σ net_pnl (max 2¢ rounding drift
  across 7 strategies incl. shorts); monthly returns compound exactly to the
  total return; walk-forward split boundaries correct.
- Kelly sizer: correct (p·b−q)/b, half-Kelly, 0–5% clamps, <30-trade
  fixed-fractional gate.
- Trailing stops: direction-correct for LONG/SHORT, never widen.
- Performance metrics: daily-return-based Sharpe/Sortino/Calmar/VaR/CVaR with
  proper fill-forward and edge-case caps.
- RL merge_backtest_state: bounded alpha/beta blending, no trade-count
  double-counting. Indicators: session VWAP, Wilder RSI, true MACD histogram.

Re-verified after fixes: 12 tests passed / 2 torch-skips, server boots ~2s,
all 5 markets' risk endpoints 200 with equity-correct payloads.
